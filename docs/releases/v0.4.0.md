# OmniDrop v0.4.0 Alpha — Safer File Operations and Workflow History

OmniDrop v0.4.0 Alpha is a **Windows 10/11 x64 portable preview**, not a production-stable Office replacement. It builds on v0.3.0's self-contained C++/Qt desktop GUI, CLI and verified isolated Python 3.13.16 runtime.

## What's new

### Transactional batch renaming with verified Undo

- Review a literal/regex rename preview before changing names.
- **Prepare & apply...** hashes the selected inputs and writes a local journal. Preparation alone never renames files; applying requires a second affirmative confirmation.
- Exclusive same-directory operations refuse existing targets rather than overwriting data.
- **Undo last batch** verifies fingerprints and free original names before restoring; the CLI can list, inspect, undo and explicitly recover interrupted transactions after a restart.
- Supported bounds: 1–128 files, 512 MiB total. Case-only renames, swaps, directory moves, cross-volume moves, symlinks and unattended workflow/watch rename are deliberately unsupported.
- A multi-file transaction is *not* one atomic OS operation. A crash may leave a partial state that requires explicit recovery. Recovery never silently overwrites unrelated files.

[Rename transactions and limitations](../RENAME_TRANSACTIONS.md)

### Durable Workflow Jobs timeline

- Jobs now keep up to **160 local events per job**, including queued, started, action progress, node completion, failed, stopped, interrupted and completed milestones.
- Inspect the selected job's history in the Workflow **Jobs** panel or from the CLI:
  `omnidrop-cli workflow events <job-id>`.
- Event records contain typed operational metadata, not raw worker payloads or source/output file paths. Older `schema_version=1` job stores without events still load normally.
- Retrying a failed job re-runs the **entire** workflow. This release does not implement per-node checkpoint resume or unattended retries.

[Workflow timeline event contract](../WORKFLOW_TIMELINE.md)

### Other file tools developed since the previous release

- Read-only exact-duplicate reports for explicitly selected files, without deletion.
- Non-destructive filename previews and additional PDF tools (including embedded-image extraction).
- Existing image, text, ZIP, translation and optional Piper voice actions remain capability-gated by installed processors or separate model packs.

Check the [action catalog](../ACTIONS.md) for exact Action IDs and availability.

## Download and verify

Download both:
- `OmniDrop-0.4.0-windows-dev.zip`
- `OmniDrop-0.4.0-windows-dev.zip.sha256`

Verify the archive checksum, extract it to a dedicated directory **outside a Git checkout**, then run `OmniDrop.exe`. The portable bundle includes Qt and the isolated Python runtime; no system Python installation is required. Optional Argos language packs and Piper voice models are not included.

In PowerShell:

```powershell
Get-FileHash .\OmniDrop-0.4.0-windows-dev.zip -Algorithm SHA256
Get-Content .\OmniDrop-0.4.0-windows-dev.zip.sha256
.\omnidrop-cli.exe --version
.\omnidrop-cli.exe worker-ping
```

The release pipeline verifies the package's SHA-256 and GitHub signed build provenance against the exact tested `main` commit. You can independently verify provenance with GitHub CLI:

```powershell
gh attestation verify .\OmniDrop-0.4.0-windows-dev.zip --repo stloendays/OmniDrop-Alpha --signer-workflow stloendays/OmniDrop-Alpha/.github/workflows/build.yml
```

**A signed GitHub build attestation is not an Authenticode publisher signature.** Unless a trusted publisher certificate is configured, the Windows binaries remain unsigned and SmartScreen may warn. This is a ZIP portable preview, not a signed installer.

## Compatibility and QA

- Existing Action IDs, Python worker protocol v1, Workflow JSON schema and prior CLI operations remain compatible.
- Windows CI covers CTest, Python unit tests, Qt offscreen GUI transaction tests and package smoke; Linux CI covers the core, CLI and Python tests.
- No background automatic updates, OCR, full Office-layout editing, unrestricted plugins or seamless per-node resume are claimed.
- Release assets are published only after a successful matching main-branch build and signed provenance verification.
