# OmniDrop v0.2.0 Alpha — Windows x64 Preview

This is the first public **Alpha pre-release** of OmniDrop, a local-first file processing application built with C++20 / Qt 6 and an optional Python worker.

## Highlights

- Drag-and-drop file inspector, available action catalog, searchable actions, recent files and activity history.
- Local text, image, PDF and ZIP actions, with non-destructive output paths.
- Workflow v1: reusable `.omniworkflow.json` pipelines, dependencies, branching and joining, plus a Qt graph editor.
- Workflow v2.1: live per-file progress with safe cooperative stop between actions.
- Workflow v2.3: durable local Jobs queue with explicit rerun, multi-process locks and interruption detection.
- Workflow v2.4: **opt-in folder watching**, stable-file gate, suppress generated outputs, prevent duplicate folder watchers and record arrivals as local Jobs.
- CLI equivalents for inspect, actions, workflow validation, execution, Jobs, and folder monitoring.
- Optional offline Piper voice packs and Argos translation, plus explicitly consented remote translation providers.

## Downloads

`OmniDrop-0.2.0-windows-dev.zip` — Windows x64 portable Alpha *development preview* package.
`OmniDrop-0.2.0-windows-dev.zip.sha256` — SHA-256 checksum of the ZIP, verified in release automation.

**Requirements:** Windows 10/11 x64 and a compatible **Python 3.10+** executable available through `python` on PATH or `OMNIDROP_PYTHON`. The ZIP bundles Qt and selected Python worker libraries, **not** the Python interpreter. Unzip into a dedicated folder outside a Git checkout, then launch `OmniDrop.exe`.

This is **not** a signed MSI/EXE installer, a self-contained Python runtime, an automatic update package, or a production-stable release. Microsoft SmartScreen may warn for unsigned software. Do not run untrusted downloaded programs without verifying the source and checksum.

The optional Piper TTS runtime/voice weights and Argos language models are not bundled. No online translation is triggered without its separate explicit approval.

## Security and compatibility

- Existing workflow schema version 1, Action IDs and CLI commands remain valid.
- Folder watching never starts automatically and stops when the foreground GUI session closes. Existing files are ignored on arm.
- Source files are not intentionally overwritten by built-in file transforms. Saved Jobs store selected filesystem paths locally.
- A Jobs retry reruns the full graph rather than guessing a mid-step recovery point.
- Release assets originate from a CI-tested **main** commit; ZIP hash is checked before publishing.

## Getting started

From the Workflow Builder in the GUI, add steps, preview, and run. Select **Watch folder...** only if you want an explicit single-folder monitoring session.

PowerShell example (from the extracted folder):

```powershell
.\omnidrop-cli.exe --version
.\omnidrop-cli.exe workflow validate .\workflows\examples\text-clean.omniworkflow.json
.\omnidrop-cli.exe workflow watch .\workflows\examples\text-clean.omniworkflow.json C:\Incoming --max-files 5
```

## Known limitations

- Alpha QA and tests do not replace production security review.
- Windows is the packaged desktop target; Linux currently receives core/CLI CI tests, not a supported desktop package.
- File watching is one-directory, non-recursive and session-only.
- No workflow checkpoint-only retry, durable timeline, auto-update rollback, signed installer, or unattended tray service yet.
- Some operations require optional models/runtime dependencies.
